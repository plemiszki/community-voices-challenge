# The Community Voices Challenge

## Summary

This is my submission for the Community Voices Challenge. I chose Reddit's `r/gamedev` (for game developers) as my community, and built a Rails + React/TypeScript app that uses Retrieval-Augmented Generation (RAG) to produce a "Community Voices Document", which summarizes what the community discussed over the past week and predicts what it's likely to discuss next.

Real `r/gamedev` posts and comments are embedded (via Voyage AI) into a pgvector-backed Postgres table, then retrieved by semantic similarity to ground the document generated by Claude — rather than letting the model guess. The app also includes a 2D visualization of the embedding space, a leaderboard of which content gets retrieved most often, and a side-by-side A/B comparison against the same LLM generating without any retrieved context, so you can see directly what RAG buys you.

## Set up

Step 1 - This repository includes a Dockerfile for running the app within a self-contained environment on your computer. Install [Docker](https://www.docker.com/products/docker-desktop), if necessary, and make sure the Docker daemon is running.

Step 2 - Clone the repository.

```
git clone https://github.com/plemiszki/community-voices-challenge.git
```

Step 3 - `cd` into the directory.

```
cd community-voices-challenge
```

Step 4 - Set the Rails master key, which is used to decrypt the API keys used in the app. I have sent you this key in an email.

```
export RAILS_MASTER_KEY=<key>
```

Step 5 - Build the Docker image and start the container. The first build may take a few minutes.

```
docker compose up --build
```

Step 6 - Navigate to [localhost:3000](http://localhost:3000).

## Explanation

### Ingestion

The raw data is a one-time, manually collected snapshot rather than a live crawler. I initially tried the standard approach — Reddit's public `.json` endpoints, then registering an OAuth app as a fallback — but both were blocked: unauthenticated requests from this environment returned `403`s (Reddit's anti-bot measures), and their developer app registration is currently gated behind a new "Responsible Builder Policy" that didn't resolve either — I was not able to get a client ID or secret. Due to time constraints, I decided to collect the data manually: the top 100 posts from `r/gamedev`'s past week, plus the full comment threads for the 15 most-discussed of those posts, saved as raw JSON under `db/seed_data/`.

From that raw JSON onward, everything is a real, automated, idempotent pipeline (`Reddit::Ingestor`), triggered either via `rails reddit:ingest` or the "Run Ingestion" button:

1. **Normalize** (`Reddit::SeedLoader`) — maps posts 1:1, and for comments, filters to top-level replies only (drops nested reply-to-reply threads), excludes `[deleted]`/`[removed]` content, and keeps the top 8 by score per post — capping the corpus at ~220 items so it stays cheap to embed and easy to reason about.
2. **Embed** (`Embeddings::BatchEmbedder`) — each item's title + body (comments are prefixed with their parent post's title for context, since a bare comment carries little meaning on its own) is embedded via Voyage AI's `voyage-4-lite` model, in a single batched API call, and stored in a `vector(1024)` column on the `reddit_items` table via `pgvector`.
3. **Flatten for visualization** (`Embeddings::PcaReducer`) — runs PCA (via Rumale, using its `fpt`/power-iteration solver — no external BLAS dependency needed) to project each 1024-dimensional embedding down to the 2D `(x, y)` coordinates shown in the "Embedding Space" chart.

Re-running ingestion is safe — it's idempotent on Reddit's own IDs, so it updates rather than duplicates.

### Generation

Two independent generators produce the two sides of the A/B comparison, both calling Claude (`claude-sonnet-5`) directly — the difference is entirely in what each one is given to work with.

**With RAG** (`Rag::DocumentGenerator`):

1. **Retrieve** (`Rag::Retriever`) — runs two separate semantic searches against the embedded corpus: a retrospective query ("what are the main topics discussed this week") for the "past week" section, and a prospective query ("unresolved questions, upcoming events, announced releases") for the "predicted next week" section. Each search increments `retrieval_count` on every item it returns — that's what powers the "Most Retrieved" table and the point sizes in the embedding scatter plot.
2. **Assemble the prompt** — the retrieved excerpts are numbered and embedded directly into the prompt as cited context; Claude is instructed to reference them inline by number (e.g. `[3]`) rather than write out URLs itself.
3. **Cite the sources ourselves** — after Claude responds, a "Sources" list mapping each citation number to its real Reddit permalink is appended by the app, not generated by the model. This guarantees every link in the final document is real — Claude never gets the chance to hallucinate a URL.

**Without RAG** (`Baseline::DocumentGenerator`): calls Claude with only the community name and the real date range of the ingested week (so both sides are answering about the same week) — no retrieved excerpts, no citations, and an explicit instruction not to fabricate specific post titles, usernames, or URLs it doesn't actually have.

The difference in practice is stark: the baseline reliably falls back to generic, hedged industry commentary ("likely," "probably," "typical of this community") with no real citations, while the RAG version cites specific real threads, quotes real statistics from the source posts, and grounds its predictions in concrete signals — an announced follow-up event, an unresolved discussion thread — rather than general knowledge of game-dev communities.

### Testing

The backend is covered by an RSpec suite (~70 examples) spanning models, services, and request specs. All outbound API calls (Claude, Voyage) are stubbed via WebMock, so the suite never makes real network requests or costs money to run.

With the app running (`docker compose up`), you can run the suite inside the container from a second terminal, using the command below:

```
docker compose exec -e RAILS_ENV=test -e DATABASE_URL=postgres://postgres:postgres@db:5432/community_voices_challenge_test app sh -c "bin/rails db:prepare && bundle exec rspec"
```
