# The Community Voices Challenge

## Summary

This is my submission for the Community Voices Challenge. I chose Reddit's `r/gamedev` (for game developers) as my community, and built a Rails + React/TypeScript app that uses Retrieval-Augmented Generation (RAG) to produce a "Community Voices Document", which summarizes what the community discussed over the past week and predicts what it's likely to discuss next.

Real `r/gamedev` posts and comments are embedded (via Voyage AI) into a pgvector-backed Postgres table, then retrieved by semantic similarity to ground the document generated by Claude — rather than letting the model guess. The app also includes a 2D visualization of the embedding space, a leaderboard of which content gets retrieved most often, and a side-by-side A/B comparison against the same LLM generating without any retrieved context, so you can see directly what RAG buys you.

## Set up

Step 1 - This repository includes a Dockerfile for running the app within a self-contained environment on your computer. Install [Docker](https://www.docker.com/products/docker-desktop), if necessary, and make sure the Docker daemon is running.

Step 2 - Clone the repository.

```
git clone https://github.com/plemiszki/community-voices-challenge.git
```

Step 3 - `cd` into the directory.

```
cd community-voices-challenge
```

Step 4 - Set the Rails master key, which is used to decrypt the API keys used in the app. I have sent you this key in an email.

```
export RAILS_MASTER_KEY=<key>
```

Step 5 - Build the Docker image and start the container. The first build may take a few minutes.

```
docker compose up --build
```

Step 6 - Navigate to [localhost:3000](http://localhost:3000).

## Usage

Step 1 - Click the "Run Ingestion" button to ingest the raw JSON data from Reddit, and create embeddings for each post and comment. The "Embedding Space" visualization will be available after this step.

Step 2 - Click the "Generate Documents" button to generate the two documents - one with RAG and one without. You can then read and compare the documents, side by side. The "Most Retrieved" table, showing which posts/comments were retrieved most often, will be populated after this step.
